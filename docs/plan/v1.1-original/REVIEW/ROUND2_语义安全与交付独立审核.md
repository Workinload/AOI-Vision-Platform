# 第二轮审核：工业安全、双机真实性、场景覆盖、交付闭环

审核日期：2026-10-15。审核独立于第一轮的主关注点：**真实双进程网络、模拟硬件隔离、逐料质量安全、互锁/换型、无损资产、UI数据真实性、跨机日志以及是否有虚假验收声明**。对最终修订 PLAN、`SIMULATION_CONTRACT.md`、40+ 负测、所有 Agent 工作令与 `EXIT_GATES.csv` 交叉验证。

## 针对危险失败模式的复核结论

- **不是单进程假双机**：至少启动两个角色不同的 `aoi-core`、两个独立 Qt UI 和一个 `vplc` 五进程；Master/Slave 独立 WAL DB、独立 Assets/Outbox、真实 TCP 和 IPC。vPLC FINS/UDP 报文有抓包/事务证据。
- **CamDone 不等于 OK**：采到帧、PLC 采图应答和最终 D1016 三种完成分别建模；末端 D2099 单独处理，漏图、模糊 ID、超时、模型报错及跨 Epoch 必须 fail closed。
- **9 硬件、11 输出**：7面阵+2线扫两光，每套线扫单父帧/两通道，对应原始 8200×15000 123MB 与旧分行规则; 单独做真尺寸压力，不把小样图的速度报告当现场吞吐。
- **所有 PLC 生产写入封闭**：SimOnly 禁止生产驱动路径，端点限本机虚拟服务；14 FG 保持未实证，初始 7 BLOCKED/7 OPEN 均不可自动升级。旧坐标、D1013、扫码字长/末端出料危险项有负测。
- **算法 mock 与真实 AI 区别**：MockProvider 用于流程/结果图/UI/业务；OpenVINO 真实 ONNX smoke 单独验推理链；绝不声称已通过电池缺陷识别准确率。
- **主从结果持久**：MessageId+PayloadHash、持久 Outbox/Inbox、ACK 分层和重复幂等；数据库和资产跨资源持久化需要 PENDING/核验/灾难恢复。
- **一键换型 fail safe**：主从 hash/Epoch/设备 readback 与虚拟 PLC 尺寸读回一致才能 ACTIVATED；失败/HOLD 后必须确证旧参数读回才能解除。
- **工程 UI 真实**：11图同屏、ROI 与算法分离、地图与信号表同源、报警点击跳转、参数编辑生成 Draft，所有显示状态来自 Core；UI 崩溃 Core继续执行，真实 Qt 截图而非 HTML。
- **发布过程真实**：先保存源码和 Windows x64 ZIP/hash，再使用 Wine 10 测实际 Windows PE；原生 Windows、真实硬件和真实现场节拍仍为 `NOT_VERIFIED/FIELD_PENDING`。

## 审核结论与剩余风险

**PLAN 通过两轮计划级审核，可以作为多 Agent 的执行分工基线。** 这不是工业功能安全认证、也不是软件编译/运行通过。以下风险仍真实存在且被计划明确纳入 Gate：

1. 模拟阶段仍需实际实现和执行全部模块/测试；当前 130 WBS、114 RQ 执行状态为 NOT_STARTED / NOT_RUN，44 注入场景亦 NOT_RUN。
2. 现场 14 项 FG 需要硬件、现役 PLC 源码/读回、真图与签核；尤其 D1030/D1000、D1013、扫码、NG 出料和真实模型质量不能凭纸面解决。
3. 真正 Windows 10/11 原生测试需用户或对应 Windows 环境；Wine 仅是预验。正式模型推理必须用实际模型，通用 YOLO smoke 不是电池工艺指标。
4. 工程排期、产线 SLO、SSD容量与保留策略在未现场量测前都不在计划中虚设“已签收”数值。

审查人逻辑：第一轮以需求覆盖与依赖结构为主；第二轮以硬件隔离/业务安全/验收真实性为主，两轮均在本会话中按审计程序真实复核。它们不能代替未来软件的 A0/A10 独立代码审查。
