AOI Vision Platform - Windows x64 SIM_ONLY Preview
===============================================

This is a runnable, framework-dependent Windows PREVIEW, NOT production AOI.
Prerequisites: Windows 10/11 x64, .NET 10 Desktop Runtime x64, compatible
OpenCV native runtime/dependencies. The app includes C# + Avalonia + OpenCvSharp5.

QUICK START
1. Extract the entire artifact to a writable folder, for example Downloads\AOI_SIM11.
2. Ensure no other AOI SIM Core/vPLC is using localhost ports 19600,19610,19621,19622.
3. Double-click Launch-SIM11.cmd. Three Core/vPLC consoles and two UI windows start.
4. Observe 9 VIRTUAL physical image devices mapped to 11 logical OpenCV5 channels.
5. The simulated Master Core persists 11 results, six from Slave PeerLink.
6. Close all five SIM process windows before restarting. Delete sim-data only when
   you intentionally want a fresh simulated workpiece; retain it for audit otherwise.

After running, capture diagnostic evidence (read-only):
  Diagnostics\AOI.Diagnostics.Cli.exe capture sim-data sim-data\flight.jsonl
  Diagnostics\AOI.Diagnostics.Cli.exe replay sim-data\flight.jsonl
  Diagnostics\AOI.Diagnostics.Cli.exe bundle sim-data\flight.jsonl sim-data\evidence.zip
  Diagnostics\AOI.Diagnostics.Cli.exe verify sim-data\evidence.zip

REAL SAFETY BOUNDARIES
- No OEM camera SDK or PLC production transport. FINS/UDP is hardwired to 127.0.0.1.
- No REAL hardware writes, interlocks, machine motion or factory ejection enabled.
- Only tiny synthetic pixels; NOT 8200x15000 full line-scan performance proof.
- AOI quality result is SIM_ONLY, not trained OCR/defect inference or field acceptance.
- The exit barcode is a test fixture echo, not an independent industrial scanner.
- Windows interactive GUI rendering was not field-tested; CI tested compilation
  and separate headless IPC but not an operator's monitor/device drivers.
- Changeover module exists as an isolated offline library; this launcher does NOT
  activate certified product changes or bypass industrial safety gates.
- DO NOT connect this preview to any real PLC, camera or production wiring.

Build details and exact dependency pins are in the repository C# migration branch.
GitHub: https://github.com/Workinload/AOI-Vision-Platform

CONTINUOUS SIM_FULL MODE

Launch-SIMFULL.cmd starts 5 SIM_ONLY virtual workpieces with 11 channels each,
up to 3 simultaneously on the virtual conveyor. Uses sim-full-data rather than
the SIM_LIGHT folder. Run only in a fresh writable folder.
A previous Core WAL or changed vPLC boot proof causes HOLD, never auto-release.
D4000-D4009 are reserved solely for loopback virtual machine tests.
There is no actual conveyor, industrial sensor, camera SDK or production model.


A6 SIM_ONLY PRODUCT SOLUTION / STATION RECIPE

NEW: Recipes\\AOI.Solutions.Cli.exe is an offline, versioned product editor.
Before FIRST SIM_FULL run, double-click Configure-SIM-Recipe.cmd to create
SIM_PRODUCT_A, edit the ST05 threshold to 110, publish immutable manifest and
commit matching hash+epoch on BOTH local A6 simulated nodes. Then run
Launch-SIMFULL.cmd. In the Avalonia "产品方案 / 换型" tab inspect the active
release ID, epoch, digest and each station's actual pixel-rule tunables.
The scheme really changes SIM_ONLY native OpenCV pixel thresholds, not hardware.

For custom OFFLINE recipes use commands from a terminal:
  Recipes\\AOI.Solutions.Cli.exe bootstrap sim-full-data S1 "Demo Product" engineer
  Recipes\\AOI.Solutions.Cli.exe tune sim-full-data S1 ST05 1 110 0.1 engineer
  Recipes\\AOI.Solutions.Cli.exe publish sim-full-data S1 engineer
  Recipes\\AOI.Solutions.Cli.exe activate sim-full-data SIMREL-<id-from-publish> engineer
  Recipes\\AOI.Solutions.Cli.exe status sim-full-data
Never activate after any production.db/sim-full-cycle.db appears. A6's
COMMITTED_HOLD state does NOT unhold a physical line, enable any real I/O, or
certify production changeover. For a new test archive the old root and start
with a NEW EMPTY sim-full-data root. No silent restart or rollback.


ROI PARAMETER DRAFTS (SIM_ONLY CORE IPC)

Both desktop windows now have a "校验并保存本机 ROI 草稿" button in
channel detail. The Windows launch script generates an ephemeral local edit
session token, inherited by only the five SIM_ONLY child processes.
Core saves each channel's normalized ROI to its OWN sim-config.sqlite WAL,
using strict revision checks and camera ownership: Master CH01/06/07/10/11,
Slave CH02/03/04/05/08/09.
An existing draft loads after IPC reconnect; an outdated revision or wrong
machine is rejected. A lost IPC session must never imply save succeeded.

ROI edits are unactivated DRAFTS ONLY. They do NOT alter native image crops,
do NOT mutate immutable A6 published station recipes, do NOT send PLC commands,
do NOT change already-finished workpieces and do NOT bypass REAL interlocks.
Keep the sim-config.sqlite evidence if archiving a simulated run.
Configuration endpoints 127.0.0.1:19641 and :19642 use a short-lived session
token, are not an industrial authentication mechanism and must not be exposed
over a network.


REAL OPERATOR PNG INPUT (SIM_ONLY / native OpenCvSharp)
Set AOI_SIM_IMAGE_ROOT to a folder of actual 8-bit PNG images BEFORE invoking
Launch-SIMFULL.cmd. Use AOI_SIM_IMAGE_LAYOUT=FLAT for a single operator sample
set: CH01.png, CH02.png, CH03.png, CH04.png, CH05.png, CH06.png, CH07.png,
LINE-S-8.png and LINE-M-2.png. Without FLAT, each separate workpiece requires
a folder named after its newly assigned WorkpieceId in N format; this is mainly
for API-driven offline replay, not normal conveyor sessions.
Master/Slave load and inspect real PNG bytes, contour defects produce real NG,
missing input fails closed rather than silently switching to synthetic GOOD.
The two line-camera parent PNGs split by exact even/odd row parity. All input
and annotations remain offline, no camera SDK or PLC writes.
VisionLab/AOI.Vision.Cli.exe runs standalone image inspection and creates
annotated PNG + report.html. Run with --help for exact options.
Only published A6 ROI data is applied during the NEXT SIM_FULL run; GUI ROI
drafts by themselves never modify currently running inspections.
